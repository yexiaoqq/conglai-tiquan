# 罪己诏 · 二〇二六

> 关于「聪来提权」`v2.0-md3` 中**标称 KernelSU 3.2.5（32525）**的构建，经查**名实不符**：
> 其内嵌 ksu 实为 fork 版，驱动上报 **32653**。此过在吾，特颁此诏，明其所以，示其更正。

---

## 一、朕躬有失（过失何在）

2026-10-03 发布的 `v2.0-md3` Release 中，资产 `conglai-md3-ksu32525-signed.apk`
对外标注「内嵌 KernelSU 3.2.5（32525）」。然而在 Samsung Galaxy S23（SM-S9110）真机上
late-load 之后，`ksud debug version` 实际输出：

```text
Kernel Version: 32653
```

**标称 32525，实报 32653 —— 名不副实。**

## 二、何以至此（根本原因）

驱动上报的版本号并非字符串，而是**编译期算出的一个整数常量**：

```text
KSU_VERSION = 30000 + (构建 ko 时的 KernelSU git 提交总数) − 7
```

- 官方 v3.2.5：提交数 2532 → `30000 + 2532 − 7` = **32525**
- fork 版（diabl0w/KernelSU）：提交数 2660 → `30000 + 2660 − 7` = **32653**

构建 `v2.0-md3` 时，直接采用了 **fork 版内核源码**编译 ksud 内嵌的 `kernelsu.ko`，
于是版本号被「顺带」抬成了 32653。**失误在于：以版本命名产物，却未校验版本常量本身。**

## 三、影响所及

- 驱动上报版本（32653）与 KernelSU 管理器版本（v3.2.5 / 32525）**不匹配**；
- 可能导致管理器识别 / 版本校验异常，或提示版本不一致；
- 提权功能本身可用，但**名实不符**，且与发布说明相悖 —— 这是吾之过。

## 四、如何更正

新构建 **`v2.0.1`** 已改用**官方 KernelSU v3.2.5** 的 ksud 作为 `assets/ksud`：

- `ksud` md5 `fa6378c07089ef6223da75cdba632896`（官方 3.2.5，内嵌 ko 编于提交 2532）；
- 于 `libexp.so` 内**中和** `--ro-partitions` / `--soft-reboot` 参数（非原机 ksud 不接受这两个串）；
- 重打包、对齐、重签后产出，真机 late-load 上报 **32525**。

| 项目 | 值 |
| --- | --- |
| 文件 | `conglai-v2.0.1-ksu32525-signed.apk` |
| 大小 | 15982076 B |
| sha256 | `edda60bd4bc1ca86a4f5cad71ea888526d99fc8f85064091aaa8c18074269dd2` |
| 上报版本 | **32525**（已真机验证） |

## 五、受此诏者须知（如何更新）

1. 下载并**覆盖安装** `v2.0.1`（签名证书一致，可 `pm install -r` 升级）；
2. **重启手机** —— 热替换磁盘上的 ksud 不生效（内核已加载 KernelSU 时，late-load 会直接跳过，不换模块）；
3. 开机后核验：

   ```sh
   su -c '/data/user_de/0/df.root/ksud debug version'   # 期望 Kernel Version: 32525
   ```

## 六、诫勉（防再犯）

- 发布任何「带版本号」的产物，**必须先在真机 `ksud debug version` 校验**，不得以构建来源臆测版本；
- 版本判定的唯一权威基准（哈希表）、查法与生效条件，见
  [`KSU_VERSION_FIX.md`](KSU_VERSION_FIX.md)。
